BasicPlus — one page

A small, statically typed language for microcontrollers. One bytecode runs on a PC and on RP2350, ESP32-S3, ESP32-P4 and STM32 boards.

Module & entry point

// One file = one module = one .mod
module Hello
  import Math

  function Main()
    print "hi " + intToString(42)
  end Main
end Hello

Every block closes with what it opens: end Main, endif, next i. You never count braces. No semicolons — a newline ends a statement (a line left open inside ( ) or [ ] continues on the next one).

Variables & types

var n := 5                  // inferred: integer
var x: float := 1.5
var big: long := 1000000000L
var d: double := 2.0d
var ok: boolean := true
var s: string := "utf-8 inside"

// sized for a micro, not for a PC
var b: byte, w: word          // unsigned 8 / 16
var i8: int8, i16: int16       // signed

var buf: byte[] := newByteArray(256)
var t: integer[] := [1, 2, 3]
const PI: float = 3.14159

A byte[] costs one byte per element, not four — which matters when the whole machine has 512 KB.

Control flow

if n > 10 then
  print "big"
elseif n > 0 then
  print "small"
else
  print "zero or less"
endif

while i < 10 do
  i := i + 1
endwh

for d in devices do
  print d
next d

switch colour
  case Colour.GREEN
    print "go"
  default
    print "stop"
endsw

Also: break, continue, and compound assignment (+=, *=, mod= …).

Functions

function add(a: integer, b: integer): integer
  return a + b
end add

// default parameter values
function label(text: string, prefix := "["): string
  return prefix + text
end label

// tuples: return several values, destructure them
var ok: boolean, v: integer
{ ok, v } := Str.parseInt("123")

Public by default? No — private. Only what you mark public leaves the module.

Classes

public class Counter
  public property value: integer

  public function Counter(start: integer)
    this.value := start
  end Counter

  public function bump(d: integer)
    this.value += d
  end bump
end Counter

var c: Counter := Counter(10)
c.bump(5)
print c.value

Variables are never public. If it has to be visible it is a property, so the day you need to validate it — or guard it with a mutex — no caller changes. Single inheritance with extends, super(…), instanceof, and an Object root under everything.

What is static, and what isn’t

// Module-level declarations are static already —
// there is no keyword, and no second copy of them.
module Config
  public const MAX = 64
  public function clamp(n: integer): integer …
end Config

Config.clamp(99)        // call it qualified

// Inside a class, a static is told apart from an
// instance method by HOW YOU CALL IT:
Counter.fromString("10")   // class name  -> static
c.bump(5)                 // instance    -> method

Coming from Java or C#, this is the one habit to drop: you don’t declare static, you call through the class name.

Errors

try
  var v: integer := risky()
catch e: RangeError
  print "caught: " + e.msg
endtry

throw RuntimeError("it broke")

One hierarchy: Object → Exception → RuntimeError. Runtime faults (divide by zero, index out of range, null reference) are RuntimeError and you catch them like any other — even when the fault happens inside a function compiled to machine code.

Threads

class Worker extends Thread
  var name: string
  public function Worker(name: string)
    super(2048)          // stack size in bytes
    this.name := name
  end Worker
  public function run()
    print this.name
    yield()
  end run
end Worker

var w: Thread := Worker("A")
w.start()
w.join()

var m: Mutex := Mutex()
m.lock()  // critical section  m.unlock()

Green threads, scheduled by the VM itself — same model on the PC and on the board. Also SyncList with a blocking popBlocking() for producer/consumer.

Native: real machine code

native function fib(n: integer): integer
  if n < 2 then return n endif
  return fib(n-1) + fib(n-2)
end fib

The compiler also emits C for that function, builds it and ships a .mdn next to the .mod. Measured on a board: fib(28) 8,946 ms interpreted → 85 ms native. If the .mdn is missing or the target has no AOT yet, the bytecode still runs — same result, no speed-up. Bytecode is always the safety net.

Talking to hardware

import Gpio

function Main()
  var led: Gpio.Pin := Gpio.Pin(25, Gpio.Pin.OUTPUT)
  var i: integer := 0
  while i < 10 do
    led.on()
    sleep(250)
    led.off()
    sleep(250)
    i += 1
  endwh
end Main

Every peripheral is a class: Gpio.Pin, I2c.Bus, Spi.Bus, Uart.Port, Pwm.Slice, Adc.Channel, Rtc.Clock, Wdt.Timer, Timer.Alarm. The same program runs on every family — only the pin numbers change.

Build & run

# compile one file
java -jar basicplus-frontend.jar Hello.bp

# run it on the PC
java -jar bpgenvm.jar Hello.mod

# a project
{ "sourceDir": "src", "outDir": "out",
  "main": "App", "dependencies": [] }

From the IDE it is one menu: run on the PC, on the simulated micro or on a board — with breakpoints and variable inspection in all three.

Why it looks like this

Blocks read in both directions. You read code downwards while writing it and upwards while fixing it, so every close says what it closes.

Private by default. A program you can keep under control is one where you chose what to expose.

The same bytecode everywhere. Two independent VMs — one in Java, one in C99 — must print the same bytes for the same .mod. That rule is the backbone of the project, not a slogan.
