Credits and acknowledgements

BasicPlus is a stack of its own from top to bottom — compiler, two virtual machines, development environment — but it is not built in a vacuum. It rests on other people's work: filesystems, graphics libraries, a real-time operating system, each manufacturer's SDK, and the tools everything is built with.

This project would not have been possible without them. This page is here to name them, say what each one does inside, and say thank you.

The heart of the virtual machine

ProjectWhat it does in BasicPlusLicense
littlefs
v2.11.3		 The flash filesystem, the same one across all three micro families. It is designed for NOR memory and for a power cut not to leave the volume unusable — exactly what a device that gets plugged and unplugged needs. It is vendored in the repository (third_party/littlefs) so the build is reproducible without downloading anything. BSD-3-Clause
FreeRTOS The real-time operating system (RTOS) the VM rests on when running on a board. It is not just the scheduler: from it come the tasks — the interpreter workers and the communications one — and also the queues, semaphores, mutexes and timers that BasicPlus's Thread and Mutex classes are built on. On the Pico and the STM32 the kernel is used directly; on the ESP32s it arrives inside ESP-IDF. MIT

The graphical interface

ProjectWhat it does in BasicPlusLicense
LVGL
v9.2.2		 The whole graphical interface. The widgets Gui offers are LVGL widgets underneath, and the drawing on the boards' screens is its work. It also includes the PNG decoder (lv_lodepng, based on LodePNG) used to load images. MIT
SDL2
2.30.9		 The simulated micro's window: when you run a program with a GUI on the PC, what you see is LVGL painting onto SDL2. It is what makes it possible to develop interfaces without the board in front of you. zlib
Montserrat
typeface		 The type you see on screen. LVGL ships it compiled in several sizes and that is what fontSize selects, so it goes inside every firmware image. We also publish a bold cut as a standalone file (samples/montserrat_26_bold.bin) so the FontLoadDemo example can show runtime font loading. SIL OFL 1.1

Each micro's SDK

The firmware is the same portable engine across all three families, but each one needs its own waist: boot, clocks, flash, USB and peripherals. That part comes from the manufacturer.

ProjectWhat it does in BasicPlusLicense
Raspberry Pi Pico SDK The base of the RP2350 firmware (Pico 2 and Metro): boot, USB CDC, flash, PIO, and the peripherals that Gpio, Spi, I2c and company rest on. BSD-3-Clause
ESP-IDF (Espressif) The base of the ESP32-S3 and ESP32-P4 firmware: partition system, PSRAM, MIPI-DSI and the rest of the platform. Apache-2.0
STM32Cube (HAL + CubeIDE) The base of the STM32 firmware (Nucleo-U575 and Discovery U5G9J): peripheral HAL, the screen's LTDC, and the environment it is compiled with. BSD-3-Clause

The tools it is built with

Without listing them one by one in a table, because they are the ground you stand on: GCC and the Arm GNU Toolchain (arm-none-eabi) for native code and for AOT; CMake and Make to build the firmwares and the C VM; Maven and the JDK for the compiler, the Java VM and the IDE; and Git, which has kept every step of this.

About the licenses. All of the above are permissive licenses and their conditions are respected. The license texts of whatever travels inside the repository sit next to their code — for example bpgenvm-c/third_party/littlefs/LICENSE.md — and the technical detail of which version is used and how to update it is in bpgenvm-c/third_party/README.md. BasicPlus is published under the MIT license.

And one mention apart

The name is a tribute to Digital Equipment Corporation's BASIC-PLUS, the structured dialect that ran under RSTS/E on the PDP-11s in the 1970s and 80s. There is not a line of its code here — there could not be — but the idea is: a language that is simple to read and does not treat you like a beginner.
